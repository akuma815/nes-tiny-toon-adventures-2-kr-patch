## 시행착오

- baseline_attract_001은 no-input 조건 -1 처리에서 처음7프레임 Start를 지정했고, 실행 중 원천 Lua 수정으로 실제 로드된 Lua 해시도 확정할 수 없어 채택하지 않았다. 실패 이력을 보존하고 002에서는 실행 Lua/설정을 먼저 동결했다.
- 최초 프레임 PNG는 Mesen이 빈 값을 반환했다. 정상 캡처는 프레임60부터이며 0바이트 PNG는 시각 증거에서 제외한다. 이후 캡처 스크립트는 프레임1 PNG를 요청하지 않는다.
- text_trace_001은 PPU 쓰기 로그를 얻었지만 runner가 모든 스크립트에 최종 PNG를 요구해 wrapper 검사가 실패했다. 종료0과 원시 로그는 보존하되 runner 전체 PASS로 부르지 않는다.
- text_trace_002는 고정 PRG 은행의 너무 넓은 read callback/getState 비용으로 Mesen 120초 타임아웃. 정상 완료 증거에서 제외한다.
- 성공한 text_trace_003은 후보 데이터 뱅크만, text_consumer_001은 검증한 읽기 명령만 추적했다. 양쪽을 연결해 실제 데이터와 임시 은행을 확인했다.
- 추출기 최초 fingerprint의 iNES 16바이트 보정과 매크로 끝 경계의 2바이트 과대 산정을 검사 실패로 발견하고 수정했다. 출력/번역 원천을 만들기 전에 실패했고, 최종 산출물은 전체 커버리지와 데이터/포인터 왕복을 통과했다.

초기 조사 시점에는 한글 ROM이 없었다. 이후 타이틀 실험본을 아래와 같이 만들었다. 정식 배포는 아직 없다. 최종 제작자 이름·게시 위치·완료 범위는 해당 작업 시점에 기록한다.

## 타이틀 첫 구현 — 작업4/5/6

사용자가 첫 작업을 타이틀로 지정했다.1편의 PNG→생성형 번역→재삽입 방식을 따르되 실제2편 소비 경로를 조사했다. 프레임 끝 CHR만 보고는 상단 로고를 추출할 수 없었고 화면 중간IRQ/CHR17·19/NT2000·2800 전환을 연결했다. 숫자2는스프라이트라그대로보존했다.

배치 데이터가 PRG 안의 유사 패턴이 아닌 **CHR 내부 압축 스트림**이라는 점을 PPU→RAM0400 복사 추적으로 확인했다. 두 스트림의 원본110/100바이트가 실제 NT1024바이트씩으로 전개된다. generated PNG를 NES 색상·타일로 바꾼 뒤 압축63/90바이트로 넣어 원래210바이트 공간을 유지했다. 실제 리본은 논리좌표보다2픽셀 위에 표시되므로 정적 합성에도 보정했다.

첫 시안은 작은 글자 이중 축소로 획이 손실됐다. 생성 원천의 작은`툰` 형태도 별도 image_gen 편집으로 교정했다. 넓은 보조 문구 배치는 리본 외곽 침범 검사에서 출력 전에 거부됐고100×8로 줄여 보호했다. 최종003은 큰 게임명/부제를 읽을 수 있고 작은 보조 문구는8픽셀이라최종디자인검토가남는다.

## 첫 대사 한글 PoC — 작업7/8/9

사용자가 다음 단계 진행을 지시해 첫 도입 문단을 한글로 넣었다. 일본어 원문`ここはみんながしってる / アクミ・エイカーズ`에서`여기는 모두가 아는 / 애크미 에이커스` 초안을 만들었다. raw/control/pointer는 보존하고 번역 원천에1draft만 추가했다. 타이틀003도 같은 원본부터 함께 빌드한다.

원본font90/91을 복제한128/129에 Galmuri7 PNG의14글자를 넣었다. 실제font mapping과PPU2048바이트가 새ROMfont와같고 네임테이블/화면까지 이어졌다. 원본일본어·숫자는남아다음문단이정상이다. 폰트source는PNG/TTF14셀픽셀동일을확인하고OFL을보존했다.

완성 문장만 봤을 때001은 정상이었지만, 출력 도중 풍경 끝에3~9픽셀 차이가 발견됐다. 원래 문장/한글font와번역문장/원래font를 분리한 진단으로 글꼴공유 가설을 좁혔다. 원래파서는0공백을 빨리 반환해서 새문구의공백/FD 인수변경이 읽기주기를 바꾸었다. 기존FD6/7·28바이트와빈비트맵의비0코드를 사용해 같은37호출사이클로 맞췄고 실제풍경차이도0이됐다.

## 홈 대사와 글꼴 수명 — 작업10

홈의 원문`さあ どれにするの？`를 선택 화면 맥락의 초안`자, 어디로 갈까?`로 넣었다. 첫 문단128/129와는 별도로130/131font를 구성했고 기존8KiB 확장 안의 padding을 사용했다. 첫 문단과 홈을 동일한글표로 덮지 않고 실제 소비 경로를 분리했다. 홈에서는06EA가 고르는IRQfont 테이블을 거쳐 C6가font를 공급했다. 테이블 한바이트만 바꿔 기존 명령·지연을 보존했다.

문장번호가다음번호로바뀌어도현재문장은대기중화면에남아있었다. FF/06CF 선행증가와화면지우기/stream pointer완성시점을추적해 동적공급의기준을 좁혔다. 둘째문단은18글자/font패킷/원래40바이트스트림을만들고6502사이클일치까지준비했다. 아직실제동적font전환은없으므로 둘째문단한글화완료로소개하지않는다.
